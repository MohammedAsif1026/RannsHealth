01. Defense-in-Depth Model

RannsHealth deploys a defense-in-depth security paradigm across all software products and operational RCM pipelines. Security controls are layered redundantly across the perimeter, network, compute, application, and storage tiers, ensuring that no single security event can compromise Protected Health Information (PHI).

The platform is architected specifically to support healthcare providers, physician practices, hospitals, and specialty clinics requiring strict adherence to HIPAA Security Rule administrative, physical, and technical safeguards.

02. Cryptographic Stack & Key Lifecycle

All communications and stored clinical entities are guarded by modern cryptographic standards:

  • Data in Transit: Mandatory TLS 1.3 encryption across all public ingress points, web interfaces, and partner API endpoints. Weak ciphers and legacy SSL/TLS protocols are strictly disabled. HSTS is enforced.
  • Data at Rest: Database volumes, file stores, and backups are encrypted using AES-256 with Hardware Security Module (HSM) backed master key management.
  • Key Management: Cryptographic keys follow strict automated rotation policies ([Key Rotation Frequency, e.g., 90-Day Rotation Schedule]) with segregated key-custodian roles.

03. Network Architecture & Multi-Tenant Isolation

Compute resources are deployed within private Virtual Private Clouds (VPCs) with zero direct inbound internet routes to application or database tiers:

  • Subnet Tiering: Clear separation between Public Edge (WAF and Load Balancing), Application Logic (Containerized RCM microservices), and Isolated Data Tiers.
  • Logical & Physical Isolation: Tenant data is segregated using strict cryptographic tenant keys or dedicated single-tenant VPC options for enterprise health system deployments ([Enterprise Dedicated Deployment Tier]).
  • Edge Protection: Web Application Firewalls (WAF) inspect inbound payloads for OWASP Top 10 vulnerabilities, SQL injection, and automated bot scrapers.

04. Identity, Authentication & Access Control (IAM)

Access to production systems follows the principle of least privilege (PoLP) and just-in-time access provisioning:

  • Enterprise SSO & SAML 2.0: Integration with healthcare enterprise identity providers (Okta, Microsoft Entra ID / Azure AD, Ping Identity).
  • Mandatory MFA: Multi-Factor Authentication is universally enforced for all operational staff, billers, coders, and administrative accounts.
  • Role-Based Access Control (RBAC): Coders, prior auth specialists, and advisory consultants have access scoped strictly to assigned provider rosters.

05. AI Pipeline Security & PHI Redaction Architecture

The AI Labs tool suite—including rannsCDE (Document Extraction), rannsCCR (Chart Review), and rannsCPA (Prior Authorization)—is engineered with zero-trust AI guardrails:

  • No Public Model Training: Client clinical notes and claim data are strictly quarantined within customer tenants. No patient data is ever fed into public training corpuses.
  • Automated PHI De-Identification: Incoming documents undergo automated optical and linguistic entity masking to strip direct 18 HIPAA Safe Harbor identifiers prior to downstream analytic feature extraction.
  • Human-in-the-Loop Safeguards: AI-generated code suggestions and prior authorization submissions require verification by certified healthcare coders before final clearinghouse adjudication.

06. Monitoring, Threat Detection & Incident Response

All infrastructure components emit continuous telemetry into centralized, write-once audit log sinks. Automated SIEM engines monitor for anomalous access patterns, credential stuffing, and unusual egress volume.

In the event of a suspected security event, our formal Incident Response Plan activates designated triage teams, containment procedures, and client notification protocols in accordance with HIPAA Breach Notification Rule requirements ([Incident Response SLA Notice Window, e.g., Within 24-48 Hours]).

07. Regulatory Alignment & Target Certifications

Our operational controls are aligned against premier healthcare information security frameworks:

  • HIPAA / HITECH Alignment: Full adherence to Technical Safeguards (§ 164.312), Physical Safeguards (§ 164.310), and Administrative Safeguards (§ 164.308).
  • SOC 2 Type II Capability: Architecture aligned with AICPA Trust Services Criteria (Security, Availability, Confidentiality, and Processing Integrity).
  • Third-Party Audit Schedule: Independent compliance attestations and penetration testing reports are conducted on a recurring schedule ([Annual Third-Party Audit Cycle / Attestation Firm]).
